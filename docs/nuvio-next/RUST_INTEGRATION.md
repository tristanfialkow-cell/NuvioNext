# Rust core integration (Phase 1)

Nuvio Next keeps Android, Compose, Media3, QuickJS, the torrent engine and the Dolby Vision bridge in
their existing languages. `rust/` hosts **portable, CPU-bound core logic** that Kotlin calls through one
small JNI library. Background and the decision record are in [AUDIT.md](AUDIT.md) (§6 bridge choice,
§7 candidates).

## Layout

```
rust/
├── Cargo.toml              workspace, release profile (LTO, panic=unwind)
├── Cargo.lock              committed; builds use --locked
├── rust-toolchain.toml     pinned toolchain + the four Android targets
├── .cargo/config.toml      16 KB page alignment for Android targets
├── nuvio-core/             pure Rust, no dependencies (serde only in dev-dependencies)
│   ├── src/kotlin_text.rs  Kotlin/java.util.regex-compatible text primitives
│   ├── src/release_facts.rs release-name classifier
│   └── tests/              shared fixtures + fixture test
└── nuvio-core-jni/         cdylib libnuvio_core.so (jni 0.21.1)
```

Kotlin side: `app/src/main/java/com/nuvio/tv/core/nativecore/` (`NuvioCore`, `NuvioCoreNative`) and
`core/debrid/` (`ReleaseFactsClassifier`, `NativeReleaseFacts`).

## Build

| What | How |
|---|---|
| Android `.so` for all variants | Automatic: `buildRustCore<Variant>` (cargo-ndk, `armeabi-v7a`, `arm64-v8a`, `x86`, `x86_64`, API 24) feeds `variant.sources.jniLibs`. |
| Host library for JVM unit tests | Automatic: `buildRustCoreHost`; tests receive `-Dnuvio.core.hostLib=…`. |
| Build without Rust | `-Pnuvio.rustCore=false` (the app then uses Kotlin everywhere; parity tests are skipped). |
| Use Rust for release classification | Debug builds: on by default. Release/benchmark: `-Pnuvio.rustReleaseFacts=true`. `-Pnuvio.rustReleaseFacts=false` forces Kotlin everywhere. |
| Rust checks | `cd rust && cargo fmt --all --check && cargo clippy --workspace --all-targets --locked -- -D warnings && cargo test --workspace --locked` |

Prerequisites: rustup (the toolchain in `rust-toolchain.toml` installs itself), `cargo install
cargo-ndk --version 4.1.2 --locked`, and the NDK from `android.ndkVersion` (AGP resolves its path).
Gradle finds cargo via `$CARGO`, `~/.cargo/bin/cargo`, or `PATH`.

## Boundary contract (ABI version 1)

- **Versioning:** `NuvioCore.EXPECTED_ABI_VERSION` must equal `nuvio_core::ABI_VERSION`. On mismatch the
  library is treated as unavailable. Feature wrappers additionally compare enum/language tables
  (`nativeEnumTable`) with the Kotlin enums before first use. Bump the ABI version for any change to
  layouts, tables or semantics.
- **Loading:** lazy, on first use (never on the main-thread startup path), once per process. A missing
  library, unsupported ABI or mismatch yields `NuvioCore.Status.Unavailable`; nothing throws to callers.
- **Threading:** every native function is pure and reentrant, has no global state, starts no threads and
  never calls back into Java. Callers use their own dispatcher.
- **Cancellation:** calls are short synchronous batches; coroutine cancellation is honoured between
  batches by the caller. No Rust async runtime.
- **Errors:** invalid input → `IllegalArgumentException`; Rust panic → caught with `catch_unwind` and
  rethrown as `IllegalStateException`. `ReleaseFactsClassifier` falls back to Kotlin on any
  `RuntimeException`.
- **Data:** flat `IntArray`/`Array<String?>` batches, no JSON, one JNI call per batch; local references
  are released per element so large batches cannot overflow the local reference table.
- **Ownership:** Rust copies inputs into owned strings for the call's duration and writes results into
  caller-allocated arrays; nothing native outlives the call.

### Release classification layout

Per stream, `layout` holds 6 ints: text count, parsed flag, and hdr/audio/channels/languages list sizes
(`-1` for a null list — null and empty lists join differently in the Kotlin reference). `strings` holds 7
nullable fixed fields (stream quality, resolve title, parsed resolution/quality/codec/group/title)
followed by the texts and list elements. Output: 8 ints per stream (resolution, quality, visual mask,
audio mask, channel mask, encode, language start, language count), a language ordinal array and a
release-group array.

## Correctness strategy

The Kotlin implementation stays the reference. Rust reproduces the exact `java.util.regex` behaviour the
Kotlin code depends on rather than translating patterns: Java's non-multiline `$` before a final line
terminator, `IGNORE_CASE` + Kotlin's implicit `UNICODE_CASE` (`ı`, `ſ`, `K`, `İ` match `[a-z]`), Kotlin
`trim()`/`isBlank()` whitespace rules (U+001C–U+001F yes, U+0085 no), overlapping token occurrences and the
title look-ahead. Evidence:

- `rust/nuvio-core/tests/fixtures/release_facts.json` — 59 cases, expectations generated by the Kotlin
  reference (`-Pnuvio.updateFixtures=true`), checked by Kotlin, by Rust (`cargo test`) and through JNI.
- `ReleaseFactsParityTest` — seeded differential fuzz over 10 000 synthetic streams (release vocabulary,
  separators, line terminators, case-folding edge characters), malformed-batch tests, and the
  classifier entry point with the native path enabled.

## Rollout

`BuildConfig.RUST_RELEASE_FACTS_ENABLED` is **true for debug builds and false for release/benchmark**
by default: debug builds (and therefore the whole JVM unit-test suite) exercise the Rust path, while
shipped behaviour stays on Kotlin until on-device measurements (see [PERFORMANCE.md](PERFORMANCE.md))
show a benefit on TV hardware. Host measurements show a 4.5–5.5× speed-up on realistic release names.
Disabling it at runtime is `ReleaseFactsClassifier.nativeEnabled = false`.
